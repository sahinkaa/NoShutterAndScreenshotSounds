# Build and validation

Verified local toolchain: Xcode 27.1 (27A9275), Apple clang 21, iPhoneOS 27.1 SDK, ldid and RootHide Theos commit `cfba89a53a05b4a1b822121158acc3669c20602f`.

## Prerequisites

Install full Xcode and its command-line tools, Python 3 and ldid. Select the full Xcode developer directory. Use the RootHide fork of Theos with all submodules, which provides both package schemes:

```sh
git clone --recursive https://github.com/roothide/theos.git /your/toolchain/theos
git -C /your/toolchain/theos checkout cfba89a53a05b4a1b822121158acc3669c20602f
git -C /your/toolchain/theos submodule update --init --recursive
export THEOS=/your/toolchain/theos
```

The checkout needs its standard headers, substrate link stub and RootHide libraries. These are supplied by this Theos checkout and its submodules. The full Xcode installation supplies the public SDK. `Settings/vendor/Preferences.framework/Preferences.tbd` is a minimal private-framework link stub used only at build time. It is not shipped in the package. No Apple framework binary or sound file is redistributed.

## Compile

From this source directory:

```sh
export THEOS=/absolute/path/to/roothide/theos
sh build.sh all
```

Use `sh build.sh rootless` or `sh build.sh roothide` for one variant. The script runs the host checks then cleans and compiles each scheme independently. It does not relabel or convert one package into the other.

- Rootless: package architecture `iphoneos-arm64`, arm64 and modern arm64e binary slices, files under `/var/jb` and standard rootless library search paths.
- RootHide: package architecture `iphoneos-arm64e`, modern arm64e binary slice and native `jbroot` path conversion with libroothide dependencies.

Both have deployment target iOS 15.0. This is a build target only. The runtime was verified by the user on iPhone 11 Pro Max, iOS 26.0.1 with Dopamine 3 RootHide. The user also verified the standard rootless package on an iOS 16 device. iOS 15 and other versions remain unverified individually. Rootless preferences and logs use the ordinary `/var/mobile/Library` directories; installed package files use `/var/jb`. RootHide data paths continue to use native `jbroot` conversion.

Output:

```text
packages/com.sahinkaa.noshutterscreenshotsounds_1.0_iphoneos-arm64.deb
packages/com.sahinkaa.noshutterscreenshotsounds_1.0_iphoneos-arm64e.deb
validation/tests.log
validation/package-rootless.json
validation/package-roothide.json
validation/symbols-rootless/
validation/symbols-roothide/
```

Keep the matching dSYMs with the packages when investigating a crash. Files generated by the build are excluded from the clean source archive.

## Checks

The host suite compiles the actual runtime and preference persistence code with AddressSanitizer and UndefinedBehaviorSanitizer. It supplies isolated fixture classes and sound-function doubles. No real Mac audio is hooked or played.

Checks cover the target sound with both simulated ringer states, options that request playback irrespective of the ringer switch, asynchronous exactly-once completion callbacks on a serial queue, forwarding of unrelated sound IDs with original options and callback identity, live disable/enable, hook idempotence, rejection of incompatible method signatures, atomic saves, merged keys, backups and malformed-file preservation. A separate Camera fixture models the native will-capture sound decision, verifies that the getter hook is restricted to Camera and checks that photo capture and captured audio continue. Reusing the same settings object after disabling restores its original sound ID without changing stored fields. Additional cases cover Camera IDs 1119 and 1122 through every installed playback wrapper in both ringer states, preservation of their completion callbacks, restoration when disabled, no extra suppression in SpringBoard and unchanged video start/stop IDs 1117 and 1118. These fixtures check hook control flow rather than private iOS implementation behavior.

The package validator checks exact payload inventory, ownership, expected architecture slices, deployment target, library paths, preference registration including `isController = true`, icon dimensions and every signed code-page hash in each CodeDirectory. It also rejects host fixture classes and capture-configuration mutation symbols. These checks do not certify device trust or compatibility.

To validate an existing package:

```sh
python3 validate_package.py packages/com.sahinkaa.noshutterscreenshotsounds_1.0_iphoneos-arm64e.deb roothide
python3 validate_package.py packages/com.sahinkaa.noshutterscreenshotsounds_1.0_iphoneos-arm64.deb rootless
```

## Icon

The original vector is `artwork/Icon.svg`. The included AppKit renderer generates the 29, 58 and 87 pixel Settings list icons, the 512 pixel settings-page header asset and the 512 pixel preview:

```sh
xcrun swift artwork/render-icon.swift "$PWD"
```

Generated PNGs are already included, so rendering is optional when rebuilding.
